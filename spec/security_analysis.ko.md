# FCH 보안 분석

이 문서는 트리 인코딩 버전 2와 16라운드 FCH 압축 코어에 대해 현재까지
확인한 내용을 한곳에 정리한 보고서입니다. 어떤 근거가 있고 어디까지
검사했는지, 앞으로 무엇을 더 분석해야 하는지를 함께 기록합니다. 영문판은
[security_analysis.md](security_analysis.md)에서 볼 수 있습니다.

사양서에 정의된 보안 목표는 다음과 같습니다.

| 변형 | 충돌 | 원상 | 제2원상 |
| ---- | ---- | ---- | ------- |
| FCH-256 | 2^128 | 2^256 | 2^256 |
| FCH-512 | 2^256 | 2^512 | 2^512 |

아래 결과는 고정된 범위에서 재현할 수 있는 테스트 결과입니다. 설계가
퇴행했거나 축소 라운드가 약한 경우를 찾는 데는 유용하지만, 목표 공격 비용을
증명하거나 독립적인 암호분석을 대신하지는 않습니다.

## 분석 범위

FCH는 공개된 비키 해시로 가정합니다. 공격자는 메시지를 자유롭게 고르고,
함수를 원하는 만큼 계산하며, 사양과 소스 코드를 모두 알고 있습니다. 결과는
`fch_spec.ko.md`에 적힌 512비트 상태, 16라운드 ARX 압축, 1,024바이트 고정
리프, 정규 이진 트리 인코딩 버전 2, 출력별 마무리 영역에 한정됩니다.

라운드, 상수, 영역, 레코드, 패딩, 리프 크기나 트리 스케줄이 바뀌면 이
문서의 결과도 다시 측정하고 검토해야 합니다.

## 현재 구조를 선택한 이유

| 구성요소 | 의도 |
| -------- | ---- |
| 512비트 내부 상태 | FCH-512의 충돌 목표보다 낮은 내부 상태 충돌 한계가 생기지 않도록 함 |
| 정식 16라운드 | 현재 분석 기준인 8라운드 위에 8라운드 여유를 둠 |
| 형식이 정해진 128바이트 레코드 | 헤더, 데이터, 자식 상태와 마무리 정보를 구분함 |
| 영역값과 플래그 | 리프, 노드, 루트 마무리와 두 출력 크기의 압축 문맥을 분리함 |
| 정규 이진 트리 | 같은 패딩 길이에 하나의 트리만 허용하고 내용 기반 분할을 없앰 |
| 위치·범위 필드 | 서브트리의 레벨, 리프 구간, 바이트 구간과 자식 순서를 묶음 |
| 길이를 포함한 패딩 | 메시지 경계를 구분하고 원래 비트 길이를 결과에 반영함 |

이 구조는 여러 형태의 모호성을 설계 단계에서 없앱니다. 다만 구조만으로
충돌·원상·제2원상 저항성이 성립하는 것은 아니며, 압축 코어와 전체 트리
모드에 대한 분석이 함께 필요합니다.

1라운드 결과는 숨기지 않고 약한 상태로 표시합니다. 테스트가 확산이 부족한
코어와 이후 라운드를 실제로 구별한다는 뜻입니다. 2라운드부터 변화율이 50%에
가까워졌다는 사실만으로 보안 여유가 증명되는 것은 아닙니다. 현재는 8라운드를
축소 라운드 분석 기준으로 두고, 정식 코어에서 8라운드를 더 사용합니다.

### 축소 라운드 trail 자동 탐색

`tools/fch_trail_search.py`는 두 개의 고정된 8비트 입력군을 검사합니다. 첫 번째는
메시지 워드 0의 최하위 바이트에 XOR 차분 `0x01`을 적용하고, 두 번째는 워드
15의 최상위 바이트에 `0x80`을 적용합니다. 각 입력군과 라운드 수마다 256개
바이트 값을 전부 계산해 가장 가벼운 512비트 출력 차분을 찾습니다. 또 0이 아닌
모든 입력 바이트 마스크와 각 출력 비트의 상관을 정확한 Walsh 변환으로
검사합니다.

| 라운드 | 워드 0 최소 가중치 | 워드 15 최소 가중치 | 워드 0 최대 상관 | 워드 15 최대 상관 |
| ------ | ------------------- | -------------------- | ----------------- | ------------------ |
| 1 | 178 | 4 | 100.00% | 100.00% |
| 2 | 232 | 222 | 28.13% | 37.50% |
| 3 | 226 | 217 | 29.69% | 31.25% |
| 4 | 231 | 223 | 30.47% | 29.69% |

여덟 번의 완전 탐색에서 출력 차분이 0인 쌍은 없었습니다. 2라운드부터는 출력
워드 여덟 개가 모두 활성화됐습니다. 1라운드에서는 약한 trail이 그대로
드러나므로 초기 확산을 보안 근거로 잘못 해석하는 것도 피할 수 있습니다.

실행할 때마다 구체 탐색기를 16라운드 Python 기준 구현과 먼저 비교합니다. 별도
구현은 같은 ARX 연산을 Z3의 64비트 비트벡터로 모델링하고, 각 탐색에서 나온 최소
가중치 입력을 다시 계산합니다. 두 모델의 결과가 다르면 CI가 실패합니다. 이
수치는 정해진 두 8비트 입력군 안에서만 정확합니다. 더 넓은 차분, 여러 출력
비트를 묶은 선형 마스크나 8·16라운드 코어의 한계를 뜻하지는 않습니다.

### 회전쌍과 가산차분 검사

회전쌍 검사는 메시지의 모든 64비트 워드를 1·8·16·24·32·63비트만큼 돌린 뒤,
그 압축 결과를 원래 출력에 같은 회전을 적용한 값과 비교합니다. 라운드마다
3,072쌍을 검사했으며 정확한 회전 관계는 나오지 않았습니다. 모든 출력 워드가
활성화됐고 최소 거리는 210비트 이상이었으며, 회전별 평균이 50%에서 벗어난
최댓값은 0.21%였습니다.

가산차분 검사는 메시지 워드 0·5·10·15에 짧은 carry, 32비트 경계, 최상위 비트와
반복 바이트 carry를 확인하는 네 모듈러 차분을 적용합니다. 1라운드는 평균
20.74%, 최소 거리 14비트였고 일부 쌍은 출력 워드 네 개만 활성화돼 약점이
분명했습니다. 2라운드부터는 평균 49.93%~50.02%, 최소 거리 206비트 이상을
기록했고 모든 쌍에서 출력 워드 여덟 개가 활성화됐습니다. 출력 차분이 0인 쌍은
없었습니다.

이 검사는 고정된 IV, 영역값, 카운터와 플래그를 사용하는 실제 압축 문맥을
대상으로 합니다. 이런 상수도 단순한 워드 단위 회전 대칭을 깨는 데 영향을
줍니다. 따라서 내부 회전 characteristic, 더 깊은 관련 tweak 공격이나 검사하지
않은 고확률 가산 trail까지 없다는 뜻은 아닙니다.

### 차분 확률과 관련 문맥

경험적 확률 검사는 단일 비트 네 개와 이중 비트 네 개의 XOR 입력 차분을
사용합니다. 차분마다 4,096쌍을 만들고, 512비트 출력 차분을 고정된 16비트 투영
네 개로 나눠 빈도를 셉니다. 2·4·8·16라운드에서 가장 큰 버킷은 네 쌍으로
0.0977%였고, 1라운드는 세 쌍으로 0.0732%였습니다. 512비트 출력 차분이 0인
쌍은 없었습니다.

이 검사는 눈에 띄게 높은 차분 집중을 재현 가능하게 찾는 용도입니다. 512비트
전체 characteristic의 확률을 계산한 것이 아니며, 16비트 투영 결과만으로
검사하지 않은 전체 상태 trail의 상한을 제시할 수는 없습니다.

관련 문맥 검사는 같은 128바이트 블록에 대해 내부 압축 문맥 여덟 종류를
바꿉니다. 인접 카운터와 최상위 비트 카운터, 리프·노드·출력 영역과 플래그,
FCH-256·FCH-512 출력 문맥, 1비트 영역 차분과 복합 변화를 포함합니다. 1라운드는
평균 43.14%, 최소 거리 76비트, 최대 비트 편향 22.78%로 약했습니다. 2라운드부터
평균은 49.92%~49.99%, 최소 거리는 211비트 이상이었고 모든 출력 워드가
활성화됐으며 최대 비트 편향은 2.95% 이하였습니다. 같은 출력이 나온 관련 쌍은
없었습니다.

영역값, 카운터와 플래그는 공개 해시 API에서 공격자가 고르는 값이 아니라 유효한
FCH 인코딩이 정합니다. 이 검사는 내부 문맥 사이의 분리를 확인할 뿐, 관련 키
공격에 대한 증명이나 rebound·meet-in-the-middle 공격의 한계를 뜻하지 않습니다.

### Rebound와 meet-in-the-middle 탐색

축소 라운드 테스트 빌드에는 1,024비트 내부 작업 상태를 준비하고 정방향·역방향으로
라운드를 실행하는 기능을 넣었습니다. 전체 8라운드와 2라운드에서 시작하는
4라운드 구간을 왕복해 시작 상태로 정확히 돌아오는지 확인하며, 정방향 결과도
일반 압축 함수의 출력과 비교합니다. 이 기능은 `FCH_ENABLE_REDUCED_ROUND_TESTS`가
정의된 빌드에만 포함되므로 일반 해시 인터페이스에는 영향을 주지 않습니다.

Rebound형 검사는 블록의 첫 바이트와 마지막 바이트에 걸친 12비트 메시지 차분 중
0이 아닌 4,095개를 전부 확인합니다. 4라운드는 2+2, 8라운드는 4+4, 16라운드는
8+8로 나누고 1,024비트 전체 작업 상태의 차분을 측정했습니다. 중간 상태 최소
가중치는 373·455·460비트였고, 모든 중간·최종 상태에서 워드 16개가 활성화됐으며
256비트 이하의 중간 상태와 차분 0인 후보는 없었습니다. 최종 상태의 최소
가중치는 각각 455·460·462비트였습니다.

Meet-in-the-middle 검사는 의도적으로 작은 12비트 후보 공간에서 8라운드를 4+4로
나눕니다. 정방향 중간 상태 4,096개를 저장하고, 전체 내부 목표 상태에서 다른
후보 4,096개를 4라운드 역산합니다. 먼저 24비트 투영을 맞춘 다음 1,024비트
전체를 비교했으며, 투영 일치와 전체 일치는 각각 한 쌍이었습니다. 전체가 맞은
것은 심어 둔 후보 하나뿐이었습니다.

이 복구는 FCH 원상 공격이 아니라 구현과 탐색 모델의 일관성 검사입니다. 전체
내부 목표 상태와 메시지 비트 중 12비트를 제외한 나머지가 알려졌다고 가정합니다.
모든 라운드가 메시지 워드 16개를 전부 사용하므로 같은 후보를 앞뒤 양쪽에서
계산해야 하며, 독립적인 앞·뒤 변수 분할 없이 정방향 4,096회와 역방향 4,096회가
필요합니다. Rebound형 검사도 최적화된 inbound 해법이 아니라 정해진 차분군의
열거입니다. 따라서 더 강한 rebound, meet-in-the-middle, splice나 출력만 아는
공격까지 막는다는 뜻은 아닙니다.

| 축약 멀티콜리전 탐색 | 리프·노드·루트 상태 각 4,096개, 20비트 버킷 | 예상 가능한 축약 앞부분 일치는 있었지만 완전 상태 충돌은 없음 |
| 정규 트리 모양 | 리프 3~16개 | 정규 배치 14개 허용, 대체 분할 119개 거부 |
| 잘못된 트리 거부 | 순서 변경, 범위 위조, 빈틈, 겹침, 깊이 변경과 잘못된 자식 | 잘못된 모양 6개와 교체 8개를 거부하고 graft 시도 3개를 탐지 |
| 제2원상 탐색 | 16 KiB 목표, 변형 방식 8개로 후보 512개 | 일치 없음, 최소 거리는 FCH-256 103비트·FCH-512 227비트 |
| 장문 탐색 | 256 KiB 메시지의 변형 15개 | 충돌 없음, 최소 거리는 FCH-256 108비트·FCH-512 229비트 |
| Expandable message 접합 탐색 | 같은 2 KiB 접미사를 쓰는 장·단문 96쌍, 중간에 리프 1~4개 삽입 | 루트·해시값 일치 없음, 최소 거리는 루트 216비트·FCH-256 108비트·FCH-512 225비트 |
| Herding 수렴 탐색 | 서로 다른 1리프 접두사 256개 뒤에 같은 3 KiB 접미사 연결 | 완전 루트·해시 충돌 없음, 해시 최소 거리는 95비트·207비트 |
| 다중 표적 탐색 | 표적 64개와 후보 256개, 해시 비교 16,384회 | 일치 없음, 최소 거리는 91비트·204비트 |
| FCH-256·FCH-512 재사용 탐색 | 0~8 KiB 메시지 256개 | 설계대로 출력 전 루트는 모두 같았지만 FCH-256이 FCH-512의 어느 256비트 절반과도 일치하지 않음 |
| 깊이별 확산 | 8 KiB 트리에서 비트 변화 128회 | 리프·중간 노드·루트 평균이 모두 50% 부근으로 유지됨 |

멀티콜리전 검사에서 나온 20비트 앞부분 일치는 의도적으로 결과를 짧게 잘랐기
때문에 생기는 예상 가능한 birthday 현상입니다. 그 쌍들이 512비트 전체 상태
충돌로 이어지지 않았다는 점을 확인한 것이며, 이 제한된 검사만으로
멀티콜리전 저항성이 증명되는 것은 아닙니다.

Expandable message 검사는 접두사와 마지막 2 KiB 접미사를 유지한 채 그 사이에
완전한 리프 1~4개를 삽입했습니다. 장·단문 96쌍 중 원시 루트나 해시값을 재사용한
쌍은 없었습니다. Herding 검사는 서로 다른 첫 리프 256개 뒤에 같은 3 KiB를
붙였습니다. 이번 실행에서는 20비트 루트 투영조차 겹치지 않았고, 전체 루트와
해시값도 수렴하지 않았습니다.

다중 표적 검사는 서로 독립적인 4 KiB 표적 64개와 변형 후보 256개를 모두
비교했습니다. 출력 크기마다 총 16,384회를 비교했으며 일치는 없었습니다. 이들은
입력과 범위가 고정된 결정적 탐색입니다. 압축 함수 충돌을 먼저 만들거나, bridge
블록을 최적화하거나, expandable message·diamond·herding·다중 표적 공격의
점근적 비용을 계산하지는 않습니다.

FCH-256과 FCH-512는 의도적으로 같은 트리 루트에서 출력 마무리를 시작합니다.
그 뒤 출력 크기와 영역값을 담은 출력 레코드가 두 변형을 나눕니다. 메시지 256개
모두에서 출력 전 루트는 같았지만 FCH-256 해시값이 FCH-512의 앞·뒤 256비트와
같아진 경우는 없었습니다. 최소 거리는 107비트와 106비트, 평균은 49.52%와
49.69%였습니다. 표본 안에서 구현된 영역 분리를 확인한 결과일 뿐, 두 변형 사이의
계산 재사용 공격이 불가능하다는 증명은 아닙니다.

## 조건부 트리 보안 논증

트리 모드는 역할이 구분된 세 함수로 나누어 생각할 수 있습니다.

- `Leaf(구조 정보, 데이터)`는 512비트 리프 상태를 만듭니다.
- `Node(구조 정보, 왼쪽 구조 정보와 상태, 오른쪽 구조 정보와 상태)`는 512비트 내부
  노드 상태를 만듭니다.
- `Output(변형, 루트 구조 정보와 상태, 원본 길이, 패딩 길이)`은 최종 해시값을
  만듭니다.

여기서 각 함수는 영역값, 플래그, 카운터와 마지막 레코드 표시까지 포함한 전체
레코드 처리 과정을 뜻합니다. FCH-256의 `Output`에는 256비트 절단이 포함되고,
FCH-512는 마무리된 상태 전체를 반환합니다.

다음 세 성질은 암호학적 가정이 아니라 현재 형식에서 바로 확인할 수 있습니다.

1. **패딩은 단사입니다.** 마지막 8바이트에 원본 비트 길이가 들어가고,
   그 앞의 `0x80`이 메시지와 0 채움 영역을 구분합니다. 따라서 유효한 두 패딩
   문자열이 같다면 원본 길이와 메시지도 같습니다.
2. **트리는 하나로 결정됩니다.** 패딩 길이가 리프 수를 정하고, `n`보다 작은
   가장 큰 2의 거듭제곱을 왼쪽 자식에 배정하는 규칙이 모든 분할을 재귀적으로
   정합니다. 따라서 리프 수에 대한 귀납으로 각 범위의 트리와 구조 정보가 하나로
   결정됩니다.
3. **레코드의 역할과 위치가 겹치지 않습니다.** 리프, 노드, 자식과 출력
   레코드는 서로 다른 태그, 영역값과 플래그를 사용합니다. 구조 정보는 레벨,
   리프 범위, 바이트 범위와 자식 번호를 포함하므로 순서 변경, 위치 이동이나
   재그룹화는 적어도 하나의 입력 필드를 바꿉니다.

이 세 항목은 인코딩 성질입니다. 서로 다른 레코드가 서로 다른 상태를 만든다고
가정하지는 않습니다. 그 부분은 별도로 분석해야 하는 암호학적 성질입니다.

### 충돌의 위치

서로 다른 메시지 `M`과 `M'`이 한 변형에서 같은 해시값을 만든다고 가정하고,
두 `Output` 함수에 들어가는 전체 입력을 비교합니다.

- 입력이 다르다면 그 쌍은 이미 최종 출력 함수에서의 충돌입니다. FCH-256에서는
  의도된 256비트 절단 때문에 생기는 충돌도 여기에 포함됩니다.
- 출력 입력이 같다면 두 루트 구조 정보와 루트 상태도 같습니다. 두 정규 트리를
  루트부터 아래로 비교했을 때 서로 다른 자식 묶음이 같은 부모 상태를 만들면
  `Node` 충돌입니다. 비교한 모든 노드 입력이 같다면 결국 처음으로 데이터가
  다른 리프에 도달합니다. 패딩의 단사성 때문에 이런 리프가 반드시 존재하며,
  두 리프 상태가 같다면 `Leaf` 충돌입니다.

따라서 다른 트리 모양, 자식 순서 변경, 서브트리 접합과 메시지 경계의 모호성만
이용해 같은 해시값을 얻을 수는 없습니다. 트리 해시의 충돌은 최종 출력 함수나
역할이 정해진 리프·노드 함수의 충돌로 귀결됩니다. 다만 이 결론은 각 함수가
해당 공격에 저항한다는 조건에 의존합니다.

### 제2원상의 위치

목표 메시지 `M`을 고정해도 같은 논리를 적용할 수 있습니다. 같은 해시값을 갖는
다른 `M'`은 최종 출력 함수의 제2원상이 되거나, 처음 갈라지는 리프 또는 노드에서
충돌을 일으켜야 합니다. 정규 스케줄 때문에 공격자가 목표 트리와 다른 파싱을
같은 계산인 것처럼 제시할 수는 없습니다.

아직 공격 비용까지 계산한 제2원상 한계는 아닙니다. 완전한 환원에는 리프와 내부
노드 수, 적응형 질의, 멀티콜리전 구성, expandable message와 herding, 두 출력
변형 사이의 재사용 가능성을 함께 반영해야 합니다. 이 논증은 원상 저항성도
증명하지 않습니다.

### 논증의 경계

| 항목 | 현재 상태 |
| ---- | --------- |
| 패딩과 정규 트리의 유일성 | 형식으로 확인됨 |
| 다른 모양과 위치의 거부 | 형식과 구현 검사로 확인됨 |
| 해시 충돌·제2원상의 발생 위치 | 역할별 함수의 안전성을 조건으로 성립 |
| 영역값과 태그가 만드는 독립성 | 설계 가정이며 증명되지 않음 |
| 사양서에 적힌 수치 보안 목표 | 이 논증만으로는 확인되지 않음 |
| 장문·다중 표적 공격에서의 보안 손실 | 제한 탐색만 완료, 정량화되지 않음 |

이 논증으로 남은 질문의 범위는 좁아집니다. 공격이 트리 표현의 모호성에만 기대기는
어렵지만, 압축 코어, 레코드 흡수 방식, 출력 절단이나 일반적인 트리 해시 공격을
이용할 가능성은 여전히 분석해야 합니다.

## 구현 검증

분석 대상 알고리즘과 실제 코드가 어긋나지 않도록 다음 검사도 함께 실행합니다.

- 고정 벡터와 C/Python 기준 구현 비교 96건
- 8비트 축소 라운드 완전 탐색과 Z3 입력 재검증
- 경계값과 여러 청크 분할에서 원샷·스트리밍 결과 비교
- big-endian CI를 포함한 little-endian 직렬화 확인
- 메모리 할당, reader, 오버플로와 API 수명주기 실패 처리
- AddressSanitizer, UndefinedBehaviorSanitizer와 시드 3개의 libFuzzer 스모크 실행
- 소스·테스트 번역 단위 25개에 대해 경고를 오류로 처리하는 GCC 경로 기반 정적 분석
- 8 MiB 입력의 제한 메모리 스트리밍
- CI에서 스케일링과 같은 길이 입력의 시간, 할당 횟수와 최대 힙 확인

이 검사를 통과했다는 것은 확인한 구현이 일관되게 동작했다는 뜻입니다. 구현
검사 범위가 넓다고 해서 암호학적 증명이 되는 것은 아닙니다.

### 퍼징, 정적 분석과 실행 시간 검토

독립 실행형 하드닝 검사는 이제 최대 64 KiB의 의사난수 입력 1,024개와 경계 길이
35개에서 구조화 입력 140개를 실행합니다. 구조화 입력은 0, 1, 위치 기반 수열과
교대 패턴을 포함합니다. CI의 sanitizer 기반 libFuzzer도 최대 입력을 64 KiB로
늘리고 고정 시드 3개에서 각각 2,048회, 총 6,144회 실행하도록 바꿨습니다.

GCC 경로 기반 분석은 이전에 라이브러리 소스 8개와 명령행 도구만 검사했습니다.
이제 벤치마크와 테스트 번역 단위 15개도 검사하며 축소 라운드 테스트 2개에는
필요한 빌드 플래그를 적용합니다. 범위를 넓히는 과정에서 분할 민감도 테스트의
할당 실패 경로에 누수가 하나 발견됐고, 반환 전에 성공한 할당을 해제하도록
고쳤습니다. 이 수정으로 라이브러리 코드는 바뀌지 않았습니다.

실행 시간 검사는 내용이 서로 다른 64 KiB 패턴 4개를 FCH-256·FCH-512의 원샷과
1 KiB 스트리밍 경로에서 해시합니다. 각 패턴은 해시 16회를 한 묶음으로 하여
순서를 섞은 7회 측정을 거칩니다. 같은 길이의 모든 패턴에서 할당 횟수와 최대 힙이
같아야 하며, 중간값의 최대·최소 비율이 1.50을 넘으면 실패합니다. 현재 실행은
네 경로 모두 통과했고 가장 큰 비율은 1.316이었습니다.

이 검사는 눈에 띄는 내용 의존 동작을 잡기 위한 회귀 검사이며 상수 시간 인증이
아닙니다. FCH는 비키 해시이고 메시지는 공개된다고 가정합니다. 키를 쓰는 구성,
컴파일러가 만든 명령 차이, 캐시·분기 하드웨어 카운터, 전자기·전력 누설과 앞으로
나올 최적화 구현은 이 검사 범위에 포함되지 않습니다.

## 남은 분석

앞으로 우선해야 할 작업은 다음과 같습니다.

1. 사양, 상수와 영역 배치에 대한 독립 검토
2. 위 조건부 논증을 넘어 트리 크기에 따른 손실과 장문 한계를 포함하는 충돌·제2원상
   저항성의 정량적 환원
3. 입력 범위, 여러 출력 비트 마스크와 5~8라운드까지 넓힌 MILP·SAT·SMT
   trail 자동 탐색
4. 투영 기반 경험적 확률 검사를 전체 상태 characteristic 탐색과 정량적 상한으로
   확장하고, 현재 제한된 rebound·meet-in-the-middle 검사를 최적화된 inbound,
   독립 neutral variable과 출력만 주어진 목표까지 확대
5. 현재의 제한된 전체 트리 탐색을 멀티콜리전, expandable message, herding,
   다중 표적과 변형 간 재사용에 대한 정량적 한계로 확장
6. 장시간 외부 퍼징, 하드웨어 카운터 기반 실행 시간 분석과 앞으로 나올 최적화
   구현의 부채널 평가
7. 양자 보안 목표를 제시하기 전 별도의 양자 공격 모델 작성

현재 탐색에서 공격을 찾지 못한 결과는 이 작업들의 출발점으로 봐야 하며,
더 강한 공격이 없다는 뜻으로 해석하면 안 됩니다.
