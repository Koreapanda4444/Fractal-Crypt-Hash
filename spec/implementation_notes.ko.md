# 구현 노트(Implementation Notes)

## 이식성과 오류 처리

- 회전 횟수를 64로 나눈 나머지로 정의
- 패딩과 해시 출력에 명시적 little-endian 변환 사용
- 재귀 처리 중 메모리 할당 실패를 호출자까지 전달
- 분할 길이 계산에서 size 곱셈 overflow 방지
- 분할 파생에 전용 영역과 버전이 붙은 레코드 태그 사용
- 자식 수 선택에 편향된 나머지 연산 대신 rejection sampling 사용
- 분할 가중치를 128~255로 제한해 과도한 불균형 억제
- checked 원샷 및 스트리밍 final API로 실패 상태 전달
- 리더 기반 재귀 처리로 원샷과 스트리밍 해시의 동일성 유지
- 스트리밍 입력은 익명 임시 저장소와 고정 크기 RAM 버퍼 사용
- 구조 필드를 64비트 little-endian 고정 위치로 인코딩
- 음수 깊이와 비정규 자식 범위·배치를 오류로 거부

## 설계 철학(Design Philosophy)

FCH는 확산(diffusion)을 두 축으로 구성합니다:

- 시간(time): 고정된 12라운드 ARX 압축

- 공간(space): 재귀적 프랙탈 트리 구조

재귀 구조는 충분한 국소 혼합을 대신하지 않습니다. 각 리프 블록과 자식 상태는
독립적으로 12라운드 코어를 거치며, 트리는 그 결과를 순서와 구조 정보에 묶어
전역 확산을 추가합니다.

---

## 근거(Rationale)

- 가변 n-way 분할은 균일한 구조 가정을 어렵게 만듭니다
- 512비트 전체 입력 기반 분할 파생값은 노드의 모든 바이트를 구조에 반영합니다
- 분할 헤더·데이터·출력 레코드 분리로 직접 조절하기 쉬웠던 기존 64비트
  누산 방식을 제거합니다
- 노드·자식·리프 메타데이터로 영역을 명시적으로 분리합니다
- 순서 의존 결합은 자식 위치와 길이 정보를 유지합니다
- 버전이 붙은 고유 태그와 고정 폭 레코드는 구조 필드의 경계를 명확히 합니다
- 고정 회전값의 ARX 코어는 기존 위치 의존 S-box 혼합보다 분석 대상을 명확히 합니다
- 512비트 내부 상태는 FCH-256에 출력보다 넓은 내부 경로를 제공합니다
- 재압축은 상태의 선형적 성장을 억제합니다

## 레퍼런스 구현 범위(Reference Implementation Scope)

본 구현은 다음을 우선합니다:

- 명확성(clarity)
- 결정성(determinism)
- 구조적 투명성(structural transparency)
- 분석 가능한 고정 코어

성능 최적화는 설계 정확성과 보안 분석 이후의 목표입니다.

이 설계/구현에 대해 암호학적 안전성 주장은 하지 않습니다.
