# 구현 노트

이 문서는 C 레퍼런스 구현에서 선택한 방식과 제약을 정리합니다. 규범 알고리즘은
[fch_spec.ko.md](fch_spec.ko.md)에 정의되어 있습니다.
완료한 로컬·CI 통과, 구성된 campaign과 미검증 항목은
[validation_status.ko.md](validation_status.ko.md)에 정리합니다.

## 현재 형식

C 구현과 `tools/fch_reference.py`는 모두 트리 인코딩 버전 2를 구현합니다.
메시지에서 자식 수와 가중 경계를 파생하던 구조를 1,024바이트 고정 리프와
왼쪽 완전 이진 스케줄로 교체했습니다. 실패 시 버전 1 해시를 대신 만드는
호환 경로는 없습니다.

두 출력 변형은 같은 8워드 트리 상태를 사용합니다. 리프, 노드와 두 출력
크기는 서로 다른 영역을 사용합니다. 노드 상태에는 각 자식의 512비트 상태
전체와 레벨, 리프 범위, 절대 바이트 범위가 함께 들어갑니다. 루트 표시는 출력
마무리 단계에서만 추가합니다.

## 소스 구성

`include/fch.h`와 `include/fch_stream.h`만 공개 API입니다. 연구용 hook을 포함한
내부 헤더는 `src/`의 구현 옆에 있으며 외부 사용자를 위한 지원 인터페이스가 아닙니다.

- `src/mix.c`: 초기화, 16라운드 ARX 압축 코어, 출력 마무리
- `src/fractal_split.c`: 정규 범위 구조와 이진 자식 경계 계산 및 검증
- `src/leaf.c`: 리프 헤더와 데이터 레코드 인코딩
- `src/combine.c`: 두 자식 구조 검증과 부모 인코딩
- `src/fractal_process.c`: 정규 트리를 왼쪽부터 차례로 축약
- `src/fch.c`: 원샷 패딩과 해시 직렬화
- `src/fch_stream.c`: 증분 리프 및 서브트리 처리

`src/fractal_process.c`의 leaf push와 root fold는 one-shot과 streaming이
공유합니다. workspace와 위치 비교도 내부 공통 로직을 사용합니다.

`fch_state_t`는 상태 워드와 `fch_tree_position_t`를 함께 보관합니다. 상태 옆에
구조 정보를 두어 호출자가 올바른 상태를 다른 위치에 잘못 결합하기 어렵게
했습니다.

## 정규 스케줄

과거의 내부 함수 이름 `fch_fractal_split*`는 유지하지만 그 시그니처는 지원되는
호환 인터페이스가 아닙니다. 입력 바이트를 읽거나 가변 자식 수를 파생하지 않습니다. 리프 범위에는 그 범위
하나를, 내부 범위에는 정규 자식 두 개를 반환합니다. 리더 콜백의 유효성은
검사하지만 스케줄 계산 중에는 호출하지 않습니다.

계산에 쓰이지 않던 `depth` 인자는 내부 함수에서 제거했습니다. 위치 descriptor의
실제 tree level과 debug hook은 유지합니다. leaf는 level 0이고 root의 level은
`ceil(log2(leaf_count))`입니다.

`fch_combine`은 자식이 정확히 두 개일 때만 동작합니다. 예상 부모와 분할을
다시 계산하고, 자식 구조와 상대 오프셋·길이를 검사합니다. 순서 변경, 위조,
평면 그룹, 편향 그룹, 빈틈과 겹침이 있는 배치는 거부합니다.

## 원샷 경로

원샷 API는 원본 입력, 패딩 표시, 0 채움과 8바이트 길이 필드를 bounded reader로
제공하고 리프를 왼쪽부터 처리합니다. 힙에는 64바이트 root 상태만 할당합니다.
이진 축약 작업공간에는 레벨마다 완성된 서브트리를 최대
하나만 남기며, 내부 노드는 자식 상태와 구조 정보만 사용합니다.

패딩된 메시지 전체를 할당하지 않습니다. 해시가 끝날 때까지 원본 입력을 빌려
읽고 모든 읽기 후 해시를 직렬화하므로 입력과 출력이 겹치는 동작도 유지합니다.
트리 작업공간의 슬롯 수는 `size_t` 폭으로 고정되며 플랫폼별 보조 저장공간은
제한됩니다. 전체 작업량은 패딩된 입력과 노드 수에 선형입니다.

## 스트리밍 경로

update는 보류 중인 부분 리프가 없으면 완성된 1,024바이트 리프를 reader에
직접 전달합니다. 부분 리프만 pending 버퍼에 복사하며, 호출자의 입력은 update가
반환하기 전에 처리하고 보관하지 않습니다. 완성된 리프는 즉시 압축하고 이진
축약 작업공간에 합칩니다. final에서는 보류 중인 입력과 패딩을 합쳐 최대
1,033바이트만 만들고, 마지막 한두 리프를 처리한 뒤 저장된 서브트리를 정규
루트로 합칩니다.

입력 전체의 복사본을 남기지 않고 입력을 다시 읽지도 않으며 임시 파일도
필요하지 않습니다. 저장공간은 부분 리프 하나, final 패딩 버퍼와 고정 개수의
서브트리 상태로 제한됩니다. update를 어떻게 나누더라도 리프 오프셋, 트리
구조와 최종 패딩이 같으므로 해시 결과도 같습니다.

## 이식성

구현은 호스트 바이트 순서에 기대지 않습니다.

- 상태 워드는 `uint64_t`를 사용합니다.
- 모듈러 덧셈은 C의 부호 없는 정수 연산을 따릅니다.
- 회전 횟수는 64로 나눈 나머지로 처리합니다.
- 패딩, 메타데이터와 해시는 명시적인 little-endian 연산을 사용합니다.
- 구조 값은 고정 64비트 레코드 필드에 기록합니다.
- 범위를 더하거나 곱하기 전에 overflow를 검사합니다.

CI는 Linux·macOS·Windows, 네이티브 32비트 x86과 QEMU에서 실행하는
big-endian PowerPC 구성을 검사합니다. big-endian 대상에서도 고정 벡터와
little-endian 직렬화 검사를 직접 실행합니다.

## 오류 처리

checked 원샷·스트리밍 API는 성공 여부를 반환합니다. 잘못된 포인터, 지원하지
않는 길이, 메모리 할당 실패, 리더 오류와 비정규 트리 배치를 호출자까지
전달합니다. 공개 출력 버퍼는 실패 시 0으로 지우며, 부분 해시나 다른 트리를
대신 반환하지 않습니다.

실패한 스트리밍 컨텍스트는 free 전까지 실패 상태를 유지합니다. final을 다시
호출하면 출력 버퍼를 지우고 실패합니다. 활성 컨텍스트는 한 곳에서만 소유해야
하며 복사하거나 동시에 사용하면 안 됩니다.

실패 경로 테스트는 빌드할 때 `malloc`과 `calloc`을 바꿔 끼웁니다. 원샷 root
할당을 실패시키고 두 번째 할당이 없음을 확인합니다. 스트림 컨텍스트 할당을
실패시키고, 스트림 final에 새 할당이
없다는 점과 모든 실패 뒤 출력 초기화·컨텍스트 정리를 확인합니다.

## 테스트와 벤치마크

object와 해당 dependency는 `build/obj/`, 바이너리·바이너리 dependency·benchmark·
fuzz 생성물은 `build/` 안에 둡니다. Make는 Python bytecode 생성을 비활성화합니다.
검토 후 저장한 연구 dataset은 검증 입력이며 자동 빌드 산출물이 아닙니다.

`make check`는 기존 C correctness 프로그램 7개와 CLI 회귀를 실행합니다.
정식 KAT reader는 새 테스트 파일 대신 `test_vectors.c`에 넣었습니다.
`check-reference`의 차등 입력 384개를 유지하며 `check-interoperability`는 고정
입력 54개를 C 원샷·스트리밍 계획 11개·각 출력 크기에서 겹치는 출력 위치
2개·C CLI·Python에서 검사합니다.
`check-extended`는 `test_stress.c`를 실행합니다.

native 암호분석과 트리 공격 소스는 `analysis/`에 있습니다. 통합
`fch_diffusion.c`는 다른 `.c`를 include하지 않고 avalanche·길이·패턴·트리
확산을 실행합니다. 이 실험과 trail·characteristic·조건부 계산은 `check`와
분리한 `check-research`에 둡니다.

고정 전 라운드 characteristic 보고서는 1~16라운드에서 기준 입력 128개와 단일
비트 차분 1,024개를 사용합니다. 상태·출력 가중치와 활성 워드의 최소값을
독립적으로 집계하고 상태와 출력 증거를 각각 저장합니다. `check-full-rounds`는
`analysis/full-round-characteristics-v1.json`과 정확히 일치해야 합니다.
기존 Python 분석 테스트에는 상태 최소 증거와 출력 최소 증거를 구분하는
회귀 사례를 흡수했습니다.

`tools/fch_reduced_round_analysis.py`는 같은 압축 문맥의 1~16라운드를 모두
평가합니다. 고정 프로필은 내부 상태·출력 확산, 선택한 XOR 차분, 워드 회전과
구조 입력군 일곱 종류를 함께 검사합니다. 결정적으로 생성되는 160행 JSON 결과는
`analysis/`에 보관하며, CI가 스키마를 검증하고 프로필을 다시 실행해 결과가 정확히
같은지 확인합니다. 2라운드부터 적용하는 한계값은 암호학적 상한이 아니라 회귀
감지선입니다.

`tools/fch_second_preimage_bounds.py`는 패딩·리프 경계, 장문과 최대 길이에서
FCH-512의 조건부 제2원상 비용 계산을 재현합니다. 정규 구조 정보의 호환 개수를
확인하고 완전 메시지, 역할별 함수, 직렬 압축 호출 대용 단위를 구분하며, 결정적인
프로필을 `analysis/fch512-second-preimage-v1.json`에 저장합니다. CI는 결과가
정확히 같은지 검사합니다. 이는 이상적 함수 합집합 상한과 형식 검사이며 실제
압축 함수에 대한 결과가 아닙니다.

`bench/bench_hash.c`는 64바이트부터 8 MiB까지 입력을 늘리며 프로세서 시간과
처리량을 측정합니다. FCH-256·FCH-512 원샷, 1바이트부터 64 KiB까지의 청크를
사용하는 FCH-256 스트리밍, 1 KiB와 64 KiB 청크를 사용하는 FCH-512
스트리밍을 포함합니다.

이 실행 파일에서만 구현 내부 할당 함수를 측정용 함수로 바꿉니다. 입력 버퍼와
할당기 메타데이터는 힙 집계에서 제외하며, 각 결과에 요청된 최대 힙과 해시당
할당 횟수를 기록합니다. 원샷이 64바이트 root를 한 번만 할당하지 않거나,
스트리밍이 컨텍스트 외의 할당을 수행하거나, 입력·청크 크기에 따라 스트리밍
최대 메모리가 변하거나, 해시 뒤에 할당이 남아 있으면 실패합니다. `--quick`은
같은 스케일링 검사를 유지하면서 CI용으로 측정 조합을 줄입니다.

`--baseline`은 버전이 지정된 `baseline-v1` 측정 프로필입니다. 전체 조합과
고정 입력 시드를 사용하고 각 조합이 충분한 시간 동안 실행되도록 반복한 뒤,
한 번의 워밍업과 다섯 번의 측정 패스를 조합 사이에 섞어 실행합니다. 그 중앙
프로세서 시간과 결정적인 자원 사용량을 출력합니다. `tools/fch_benchmark.py`는
이 결과를 소스·실행 환경 정보와 함께 저장하고 CPU, 플랫폼, 컴파일러와 플래그가
같은 후속 실행만 비교합니다. 처리량 한계는 바꿀 수 있지만 힙이나 할당 횟수가
달라지면 명시적인 검토가 필요합니다. `ALLOW_RESOURCE_IMPROVEMENT=1`은 검토한
감소만 허용하며 증가는 계속 거부합니다. 기본값은 모든 자원 프로필 변화를
거부합니다.

기존 `tests/fuzz_*.c` 대상 4개는 `tools/fch_fuzz.py`로 실행합니다.
이름이 있는 seed 파일 456개, 고정 시드, 제한된 smoke와 시간 제한 campaign을
사용하며 메타데이터와 로그는 `build/fuzz/`에 둡니다. 일반 push CI는 smoke와
ASan·UBSan·누수를 검사하고 예약·수동 campaign은 대상마다 600초로 구성했습니다.
로컬 ptrace 환경에서는 누수 검사를 끄고 실행해야 했으므로 완료된 CI 누수
검사 결과를 검증 상태에 별도로 기록했습니다.

## 호환성 원칙

최적화보다 해시 결과 호환성을 우선합니다. 메모리 할당, 버퍼링, 파일 탐색,
재귀와 작업 순서는 고정 벡터와 원샷/스트리밍 결과가 그대로일 때만 바꿀 수
있습니다. 태그, 영역, 플래그, 레코드 배치, 패딩, 리프 범위, 트리 스케줄,
상태 폭과 라운드 수는 알고리즘 파라미터이며 변경 시 명시적인 형식 개정이
필요합니다.
