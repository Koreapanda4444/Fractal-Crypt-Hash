# Fractal Crypt-Hash 사양서

## 0. 문서의 범위와 현재 상태

이 문서는 Fractal Crypt-Hash의 동작을 바이트 단위로 정의합니다. FCH는
암호학 연구를 위해 개발 중인 공개·결정적 비키 해시 함수입니다. 아래 보안
강도는 분석의 기준이 되는 설계 목표이며, 현재 구조에 대한 독립적인 공개
분석은 진행 단계입니다.

12절은 다음 트리 인코딩에 적용할 확정 설계를 기록합니다. C와 Python 구현이
함께 새 인코딩으로 바뀌기 전까지는 비규범 항목이며, 앞의 절들이 현재
버전 1 해시 결과를 계속 정의합니다.

영문 사양서는 [fch_spec.md](fch_spec.md)에서 볼 수 있습니다.

## 1. 보안 모델

### 1.1 공격자 모델

알고리즘과 상수, 메시지, 해시 결과는 모두 공개됩니다. 공격자는 원하는
메시지를 선택하고 FCH를 제한 없이 계산할 수 있습니다. 이 문서의 목표 강도는
고전적 계산 모델을 기준으로 하며, 양자 공격에 대한 별도 강도는 정의하지
않습니다.

### 1.2 목표 강도

| 변형 | 출력 | 충돌 | 원상 | 제2원상 |
| ---- | ---- | ---- | ---- | ------- |
| FCH-256 | 256비트 | 2^128 | 2^256 | 2^256 |
| FCH-512 | 512비트 | 2^256 | 2^512 | 2^512 |

같은 출력 크기의 이상적인 해시에서 기대하는 일반 공격 비용입니다. 현재
테스트 결과를 보안 강도로 환산한 값이 아니라, FCH가 충족해야 할 평가
기준입니다.

### 1.3 트리 구조의 목표

FCH의 트리 모드는 다음 조건을 목표로 합니다.

- 루트, 내부 노드, 리프, 자식 상태, 분할 레코드와 출력 변형을 구분합니다.
- 노드 종류와 깊이, 길이, 자식 수, 자식 위치, 오프셋과 길이를 내부 상태에
  반영합니다.
- 유효한 트리 하나에 하나의 정규 인코딩이 대응하도록 합니다.
- 멀티콜리전, herding, 상태 이식과 장문 제2원상 같은 트리 전용 지름길을
  억제합니다.
- 원샷 API와 스트리밍 API가 같은 메시지에 같은 결과를 냅니다.

### 1.4 라운드 정책

일반 해시는 항상 16라운드를 사용합니다. 분석 빌드에서는 축소 라운드 압축을
열어 두고 4·8·12·16라운드의 확산을 비교합니다. 현재는 8라운드를 축소형
분석 기준으로 삼아 정식 코어와 8라운드의 간격을 둡니다.

포함된 분석 코드는 1·2·4·8·16라운드에서 선택 차분을 탐색하고, 제한된
범위에서 선형 상관, 고정점, 2주기, 충돌과 근접 충돌을 검사합니다. 차분 경로,
회전 공격, 관련 tweak와 트리 구조에 대한 심화 분석은 계속 진행할 항목입니다.

## 2. 고정 파라미터

| 항목 | 값 |
| ---- | -- |
| 워드 크기 | 64비트 |
| 내부 상태 | 8워드 / 512비트 |
| 압축 입력 | 16워드 / 128바이트 |
| 정식 라운드 | 16 |
| 축소 라운드 분석 기준 | 8라운드 |
| 리프 기준 | 64바이트 |
| 최대 깊이 | 16 |
| 분기 수 | 자식 2~6개 |
| 분할 가중치 | 128~255 |
| 트리 인코딩 버전 | 1 |
| 분할 파생 버전 | 1 |

FCH-256과 FCH-512는 트리 전체에서 같은 512비트 상태를 사용합니다. 두
변형은 출력 마무리 단계에서 분리됩니다.

## 3. 입력 패딩

길이가 `L`바이트인 메시지 `M`에 다음 순서로 패딩합니다.

1. `0x80`을 추가합니다.
2. 필요한 만큼 `0x00`을 추가합니다.
3. `L × 8`을 부호 없는 64비트 little-endian 정수로 추가합니다.
4. 전체 길이가 최소 64바이트가 되도록 합니다.

checked API는 64비트 비트 길이 필드나 호스트의 `size_t` 계산으로 안전하게
표현할 수 없는 입력을 거부합니다. 형식상 최대 길이는 `2^61 - 1`바이트이며,
실제 플랫폼의 한계는 이보다 낮을 수 있습니다.

## 4. 재귀 처리

처리는 깊이 0과 8워드 상태에서 시작합니다.

- 길이가 64바이트 이하이거나 깊이가 16이면 리프로 처리합니다.
- 그 밖의 노드는 2~6개의 연속된 자식으로 나눕니다.
- 자식은 왼쪽부터 차례대로 재귀 처리합니다.
- 각 자식의 512비트 상태를 다시 압축해 부모 상태를 만듭니다.

음수 깊이, 지원하지 않는 상태 폭, 빈틈, 겹침, 빈 내부 자식과 범위를 벗어난
오프셋은 유효하지 않습니다.

## 5. 분할 파생

내부 노드는 자신의 전체 입력으로 512비트 분할 파생값을 만듭니다. 이 과정은
일반 ARX 코어와 분할 전용 `FCHSPLT1` 영역을 사용합니다.

### 5.1 분할 헤더

첫 압축 입력은 128바이트 `FCHSPH01` 레코드입니다. 고정 폭 little-endian
필드에 다음 값을 넣습니다.

- 분할 파생 버전
- 노드 길이와 깊이
- 상태 폭
- 최소·최대 분기 수
- 분할 가중치 범위
- 리프 기준과 최대 깊이
- 압축 블록 크기와 라운드 수
- 트리 인코딩 버전

### 5.2 입력 레코드

노드의 모든 바이트를 `FCHSPD01` 레코드로 흡수합니다. 각 레코드는 8바이트
태그 뒤에 노드 데이터 최대 120바이트를 담습니다. block-length tweak에는
실제 레코드 길이, counter에는 누적 입력 길이를 넣고 마지막 레코드에는 final
플래그를 설정합니다.

### 5.3 출력 추출

고정 128바이트 `FCHSPO01` 레코드는 설정값, 입력 레코드 수, 노드 길이와
깊이, 추출 횟수 카운터를 결합합니다.

다음과 같이 정의합니다.

```text
r = N_MAX - N_MIN + 1
t = 2^64 mod r
```

`material[0]`이 `t` 이상일 때만 값을 사용합니다. 작으면 추출 횟수 카운터를
올려 출력 레코드를 다시 압축합니다. 자식 수는 다음 식으로 정합니다.

```text
n = N_MIN + (material[0] mod r)
```

길이가 `2 × MIN_BLOCK_SIZE`보다 짧은 내부 노드는 `N_MIN`을 사용합니다.
짧은 입력이 하나의 정규 구조를 갖게 하기 위한 규칙입니다. rejection
sampling은 나머지 연산의 편향을 없앱니다.

각 자식의 가중치는 다음과 같습니다.

```text
weight[i] = 128 + (material[i + 1] AND 0x7f)
```

가중치는 128~255 범위입니다. 자식 길이를 가중치에 비례해 계산한 뒤 모든
자식이 1바이트 이상이고, 서로 겹치지 않고, 빈틈없이 부모 전체를 덮도록
보정합니다. 나눗셈에서 남은 길이는 마지막 자식에 배정합니다.

분할 함수는 공개되어 있으므로 원하는 분기 수가 나오는 메시지를 탐색할 수는
있습니다. 이 구조의 목적은 부모의 모든 바이트가 분할에 참여하게 하고, 이전
64비트 누산값에서 가능했던 값싼 국소 조절을 없애는 것입니다.

## 6. 레코드 인코딩과 압축

### 6.1 정규 레코드

- 형식 태그는 정확히 8바이트 ASCII입니다.
- 숫자 필드는 부호 없는 64비트 little-endian 값입니다.
- 고정 레코드는 128바이트이며 사용하지 않는 바이트는 0입니다.
- 데이터 레코드는 태그를 포함해 8~128바이트이며 실제 길이를 사용합니다.
- 레코드 종류마다 별도의 태그와 압축 플래그를 사용합니다.
- 루트와 일반 리프·노드 문맥은 서로 다른 영역을 사용합니다.
- 레코드 형식이 바뀌면 인코딩 버전도 바뀝니다.

주요 태그는 다음과 같습니다.

| 태그 | 레코드 |
| ---- | ------ |
| `FCHLEAF1` | 리프 헤더 |
| `FCHLDAT1` | 리프 데이터 |
| `FCHNODE1` | 내부 노드 헤더 |
| `FCHCHLD1` | 자식 상태 |
| `FCHOUT01` | 출력 마무리 |
| `FCHSPH01` | 분할 헤더 |
| `FCHSPD01` | 분할 데이터 |
| `FCHSPO01` | 분할 출력 추출 |

### 6.2 ARX 코어

압축은 16워드 작업 상태를 사용합니다. 0~7번 워드는 현재 체이닝 상태,
8~15번 워드는 고정 IV로 초기화합니다. 라운드를 시작하기 전에 counter,
실제 레코드 길이와 상태 폭, 영역, 플래그를 각각 정해진 tweak 위치에
주입합니다.

한 라운드는 열 방향 G 함수 네 번과 대각선 방향 G 함수 네 번으로 구성됩니다.
G 함수는 64비트 모듈러 덧셈, XOR와 오른쪽 회전만 사용합니다.

1. `a = a + b + x`; `d = ROTR64(d XOR a, 32)`
2. `c = c + d`; `b = ROTR64(b XOR c, 24)`
3. `a = a + b + y`; `d = ROTR64(d XOR a, 16)`
4. `c = c + d`; `b = ROTR64(b XOR c, 63)`

메시지 스케줄에는 고정 순열 10개가 있습니다. 0~9라운드는 순서대로 사용하고,
10~15라운드는 0~5번 순열을 다시 사용합니다. 마지막 라운드 뒤 각 체이닝
워드를 다음과 같이 갱신합니다.

```text
h[i] = h[i] XOR work[i] XOR work[i + 8]
```

G 함수, IV, 회전값과 메시지 순열은 BLAKE2b 구성요소에서 가져왔습니다.
FCH는 초기화, tweak 위치, 레코드 처리, 영역, 라운드 수와 트리 모드를 별도로
정의합니다.

### 6.3 리프 압축

리프는 루트 리프 또는 내부 리프 전용 영역에서 512비트 상태를 초기화합니다.
먼저 128바이트 `FCHLEAF1` 헤더를 압축합니다. 헤더에는 인코딩 버전, 영역,
리프 길이와 깊이, 상태 폭, 트리 제한, 코어 파라미터와 분할 파라미터가
들어갑니다.

리프 데이터는 `FCHLDAT1` 레코드로 흡수합니다. 태그 뒤에 메시지 데이터를
최대 120바이트씩 넣습니다. counter에는 누적 메시지 길이, block-length
tweak에는 태그를 포함한 실제 길이를 기록하며 마지막 레코드에는 final
플래그를 설정합니다. 빈 리프도 태그만 든 final 레코드 하나를 처리합니다.

## 7. 트리 결합

내부 노드는 루트 노드 또는 일반 내부 노드 전용 영역에서 새 512비트 상태를
초기화합니다. 먼저 `FCHNODE1` 헤더로 부모 길이, 깊이, 자식 수, 상태 폭과
현재 트리 파라미터를 결합합니다.

각 자식은 하나의 128바이트 `FCHCHLD1` 레코드로 인코딩합니다.

| 워드 | 필드 |
| ---- | ---- |
| 0 | `FCHCHLD1` |
| 1 | 인코딩 버전 |
| 2 | 부모 길이 |
| 3 | 부모 깊이 |
| 4 | 자식 수 |
| 5 | 자식 순서 |
| 6 | 자식 오프셋 |
| 7 | 자식 길이 |
| 8~15 | 512비트 자식 상태 |

자식 레코드는 순서대로 압축하며 마지막 레코드에 final 플래그를 설정합니다.
결합이 끝난 노드는 8개 상태 워드를 모두 유지합니다.

## 8. 출력

루트 상태는 고정 `FCHOUT01` 레코드로 한 번 더 압축합니다. 이 레코드는
인코딩 버전, 요청한 출력 폭, 내부 상태 폭, 블록 크기와 라운드 수를
결합합니다.

- FCH-256은 전용 출력 영역을 사용한 뒤 최종 상태의 앞 4워드를
  little-endian 32바이트로 직렬화합니다.
- FCH-512는 별도의 출력 영역을 사용하고 8워드 전체를 little-endian
  64바이트로 직렬화합니다.

검증 또는 메모리 할당에 실패하면 checked API가 실패를 반환하고 출력 버퍼를
0으로 지웁니다.

## 9. 스트리밍

update 호출은 입력을 익명 임시 저장소에 이어 씁니다. final 단계에서는
저장된 데이터와 가상 패딩을 임의 접근 리더로 제공하고, 원샷 API와 같은
분할·리프·결합·출력 과정을 수행합니다.

RAM 사용량은 고정 크기 입출력 버퍼와 재귀 상태로 제한됩니다. 임시 저장소는
메시지 길이에 비례하며, 입력 의존 트리 때문에 여러 깊이에서 같은 구간을
다시 읽을 수 있습니다. final은 저장소를 닫습니다. 활성 컨텍스트를 복사하거나
동시에 접근하면 안 되며, final 이후 update와 final 재호출은 실패합니다.

## 10. 분석 및 구현 상태

### 10.1 자동 분석

현재 테스트 범위는 다음과 같습니다.

| 영역 | 현재 검사 |
| ---- | --------- |
| 코어 확산 | 단일 비트·길이 변화와 축소 라운드 비교 |
| 차분·선형 성질 | 제한된 선택 차분, 출력 비트 편향, 저중량 출력과 선형 상관 |
| 주기·충돌 | 고정점, 2주기, 전체 충돌과 제한된 근접 충돌 |
| 멀티콜리전 | 리프 상태 4,096개와 파생 노드 상태 4,096개, 20비트 접두부 버킷 분포 |
| 제2원상 | 16 KiB 기준 메시지에 대한 관련 후보 512개 |
| 트리 문맥 | 이진·평면·비대칭·역순·경계 변경·상태 이식·깊이 변경 조합 |
| 장문 | 확장·절단·재배열·복사·회전·경계 수정·저엔트로피 입력을 포함한 256 KiB 변형 15개 |

멀티콜리전 테스트의 짧은 접두부는 일반적인 birthday match가 CI에서도
나타나도록 정한 값입니다. 테스트는 버킷의 비정상적인 집중과 512비트 전체
상태의 일치를 함께 확인합니다. 이 분석 코드는 더 깊은 암호분석을 위한
재현 가능한 출발점으로 사용합니다.

### 10.2 자원 사용

분할 파생은 방문한 모든 노드의 전체 입력을 읽습니다. 메시지 길이를 `L`,
실제 깊이를 `d`라고 하면 입력 읽기 작업량은 `O(L × d)`이고 `d ≤ 16`입니다.
원샷 해시는 패딩을 위해 `O(L)` 메모리를 추가로 사용합니다. 스트리밍은
애플리케이션 RAM을 제한하는 대신 `O(L)` 임시 저장공간을 사용합니다.

### 10.3 레퍼런스 구현 검사

checked API는 입력을 읽기 전에 포인터와 길이를 검사합니다. 리더나 메모리
할당에서 실패하면 부분 상태를 반환하지 않고 호출자까지 오류를 전달합니다.
실패한 스트리밍 컨텍스트는 실패 상태를 유지하고, final은 저장소를 닫으며,
final 재호출은 출력 버퍼를 지운 뒤 실패합니다.

공용 결정적/libFuzzer 하네스는 원샷과 스트리밍 결과를 비교하고 분할 범위,
수명주기와 정리 경로를 검사합니다. 8 MiB 메시지는 서로 다른 두 청크 배치로
처리합니다. CI는 x86-64 Linux·macOS·Windows에서 빌드하며, Linux에서는
AddressSanitizer와 UndefinedBehaviorSanitizer도 실행합니다.

## 11. 설계 근거

### 11.1 상태와 출력 폭

64비트 워드는 선택한 ARX G 함수와 맞고 `uint64_t` 연산으로 이식성 있게
구현할 수 있습니다. 512비트 내부 상태의 일반 birthday 규모는 `2^256`이므로
FCH-512의 충돌 목표와 맞습니다. FCH-256도 같은 상태를 사용해 트리 안에 더
좁은 경로를 만들지 않습니다.

128바이트 압축 입력은 메시지 워드 16개를 제공합니다. 한 라운드의 G 함수
8개가 16개 워드를 한 번씩 사용합니다. 출력 영역을 분리했기 때문에 256비트
결과는 512비트 결과의 단순 접두부로 정의되지 않습니다.

### 11.2 라운드와 상수

FCH는 설명하기 어려운 새 상수 집합을 만들기보다 공개된 BLAKE2b 구성요소를
사용합니다. 16라운드는 현재 8라운드 축소 분석 기준 위에 둔 공학적 여유입니다.
향후 라운드 수를 바꿀지는 통계 점수만이 아니라 실제 공격 결과를 기준으로
판단합니다.

태그와 영역, 플래그는 일부 역할이 겹치도록 구성했습니다. 태그는 레코드를
읽기 쉽게 만들고, 영역은 상태 초기화 문맥을 나누며, 플래그는 압축 순서의
역할과 끝을 표시합니다. 모두 공개 상수이며 비밀값을 포함하지 않습니다.

### 11.3 트리 파라미터

64바이트 리프 기준은 짧은 패딩 메시지를 하나의 리프에서 처리하면서 재귀
비용을 제한합니다. 분기 수 2는 재귀 진행을 보장하고, 6은 임시 자식 상태와
트리 폭의 변동을 제한합니다. 128~255 가중치는 명목상 최대·최소 비율을
2 미만으로 유지합니다. 최대 깊이 16은 재귀와 반복 읽기를 제한하며 압축
16라운드와는 관계없는 값입니다.

전체 설계의 보안 분석은 코어, 정규 인코딩, 트리 결합, 입력 의존 토폴로지,
출력 마무리와 구현이 모두 사양대로 동작한다는 조건에 의존합니다. 이 항목들이
현재 분석의 중심 대상입니다.

## 12. 확정된 다음 트리 형식

이 절은 구현에 앞서 다음 비호환 트리 형식을 고정합니다. 현재 코드가 만드는
해시 결과는 아직 바뀌지 않습니다. C 구현과 Python 레퍼런스가 함께 버전 2로
전환되기 전까지는 입력 의존 분할을 포함한 트리 인코딩 버전 1이 유효합니다.

새 형식도 재귀 트리 해시를 사용하지만 메시지 내용으로 트리 모양을 정하지
않습니다. 토폴로지는 패딩된 길이와 리프 위치만으로 결정됩니다. 따라서 같은
길이에는 하나의 트리만 대응하고, 분할 선택을 보안 근거에서 제외할 수 있으며,
입력이 더 들어와도 완성된 앞부분 서브트리를 그대로 유지할 수 있습니다.

### 12.1 고정 스케줄 파라미터

| 항목 | 버전 2 값 |
| ---- | --------- |
| 트리 인코딩 버전 | 2 |
| 패딩 형식 버전 | 1 |
| 리프 범위 | 1,024바이트 |
| 내부 노드 분기 수 | 2 |
| 리프 레벨 | 0 |
| 분할 파생 | 사용하지 않음 |
| 루트 구분 | 출력 마무리 레코드에서만 적용 |

3절의 입력 패딩은 그대로 유지합니다. 패딩된 바이트열을 `P`, 그 길이를
`P_len`이라고 합니다. `P`를 오프셋 0부터 연속된 1,024바이트 리프로 나눕니다.
마지막 리프만 1,024바이트보다 짧을 수 있으며, `P_len`이 최소 64이므로 빈
리프는 생기지 않습니다.

리프 인덱스가 `i`일 때 다음 값을 사용합니다.

```text
byte_offset = i * 1024
byte_length = min(1024, P_len - byte_offset)
first_leaf  = i
leaf_count  = 1
level       = 0
```

모든 구조 정수는 부호 없는 64비트 little-endian 값으로 기록합니다. 바이트
오프셋, 리프 수 또는 길이를 overflow 없이 표현할 수 없으면 checked API가
입력을 거부합니다.

### 12.2 정규 이진 트리

`Tree(a, n)`을 `a`번부터 시작하는 연속된 리프 `n`개의 트리라고 정의합니다.

```text
Tree(a, 1) = Leaf(a)

Tree(a, n), n > 1:
    k = n보다 작은 가장 큰 2의 거듭제곱
    left  = Tree(a, k)
    right = Tree(a + k, n - k)
    return Node(left, right)
```

이 규칙은 왼쪽의 완전 서브트리를 먼저 만드는 이진 트리를 사용합니다. 모든
내부 노드는 자식이 정확히 두 개입니다. 왼쪽 자식 뒤에 오른쪽 자식이 이어지고, 두 자식의
바이트 범위와 리프 범위는 서로 맞닿으며, 합치면 부모 범위와 정확히 같아야
합니다.

각 노드는 다음 구조 정보를 가집니다.

```text
level       = 1 + max(left.level, right.level)
first_leaf  = left.first_leaf
leaf_count  = left.leaf_count + right.leaf_count
byte_offset = left.byte_offset
byte_length = left.byte_length + right.byte_length
```

오른쪽 자식은 `left.first_leaf + left.leaf_count`번 리프와
`left.byte_offset + left.byte_length`번 바이트에서 시작해야 합니다. 이 관계를
만족하지 않는 노드는 디코더와 구현 모두 거부합니다.

### 12.3 버전 2 레코드

버전 1 레코드와 혼동되지 않도록 새 8바이트 태그를 사용합니다. 고정 레코드에서
아래에 적지 않은 워드는 0으로 채웁니다.

| 역할 | 8바이트 표기 |
| ---- | ------------ |
| 리프 헤더 | `FCHLEAF2` |
| 리프 데이터 | `FCHLDAT2` |
| 노드 헤더 | `FCHNODE2` |
| 노드 자식 | `FCHCHLD2` |
| 출력 마무리 | `FCHOUT02` |
| 리프 영역 | `FCHLDM02` |
| 노드 영역 | `FCHNDM02` |
| FCH-256 출력 영역 | `FCHO2562` |
| FCH-512 출력 영역 | `FCHO5122` |

각 표기는 8바이트 ASCII로 해석한 뒤 64비트 태그 또는 영역 필드에
little-endian으로 넣습니다. 버전 2는 분할 태그, 분할 영역과 분할 플래그를
사용하지 않습니다. 리프 헤더, 리프 데이터, 노드 헤더, 노드 자식, 출력과
final 플래그는 현재 비트 값을 유지합니다.

리프 헤더 `FCHLEAF2`에는 태그, 인코딩 버전, 리프 영역, 리프 인덱스, 바이트
오프셋, 바이트 길이, 1,024바이트 리프 범위, 내부 상태 폭, 압축 블록 크기,
라운드 수, 패딩 형식 버전과 이진 분기 수를 순서대로 넣습니다. 내부 상태 폭은
워드 수, 압축 블록 크기는 바이트 수로 기록합니다. 리프 데이터는 `FCHLDAT2`를
사용하며 counter는 해당 리프 안에서 흡수한 누적 바이트 수입니다.

리프 헤더는 counter 0과 리프 헤더 플래그를 사용해 128바이트 전체를 압축합니다.
각 데이터 레코드는 태그 뒤에 리프 바이트를 최대 120바이트까지 담습니다.
block-length tweak에는 태그와 payload를 합친 실제 길이를 넣고, 마지막 데이터
레코드에 final 플래그를 설정합니다.

내부 노드 헤더 `FCHNODE2`에는 태그, 인코딩 버전, 노드 영역, 레벨, 첫 리프,
리프 수, 바이트 오프셋, 바이트 길이, 자식 수, 리프 범위, 내부 상태 폭, 압축
블록 크기와 라운드 수를 순서대로 넣습니다. 내부 상태 폭은 워드 수, 압축 블록
크기는 바이트 수입니다.

각 `FCHCHLD2` 자식 레코드의 0~7번 워드는 다음과 같습니다.

| 워드 | 필드 |
| ---- | ---- |
| 0 | `FCHCHLD2` |
| 1 | 인코딩 버전 |
| 2 | 자식 인덱스 0 또는 1 |
| 3 | 자식 레벨 |
| 4 | 자식의 첫 리프 인덱스 |
| 5 | 자식의 리프 수 |
| 6 | 자식의 바이트 오프셋 |
| 7 | 자식의 바이트 길이 |
| 8~15 | 512비트 자식 상태 전체 |

노드 헤더로 부모 구조를 먼저 결합한 뒤 두 자식 레코드를 흡수합니다. 노드
헤더는 counter 0, 자식 레코드는 인덱스 순서대로 counter 1과 2를 사용합니다.
두 번째 자식 레코드에 final 플래그를 설정합니다. 세 레코드는 모두 해당 역할
플래그와 128바이트 전체 길이를 사용합니다.

리프가 메시지 전체를 차지하더라도 별도의 루트 리프 영역을 사용하지 않습니다.
내부 노드도 나중에 루트가 되는지와 관계없이 같은 노드 영역을 사용합니다.
루트 표시는 완성된 트리를 알 수 있는 출력 마무리 단계에서만 적용합니다. 이
규칙이 있어야 뒤에 데이터가 추가돼도 이미 계산한 리프와 서브트리 상태가
바뀌지 않습니다.

최종 `FCHOUT02` 레코드에는 태그, 인코딩 버전, 비트 단위 요청 출력 폭, 비트
단위 내부 상태 폭, 바이트 단위 압축 블록 크기, 라운드 수, 바이트 단위 원본
메시지 길이와 패딩된 길이, 전체 리프 수, 루트 레벨, 루트의 첫 리프, 루트
리프 수, 루트 바이트 오프셋, 루트 바이트 길이, 리프 범위와 패딩 형식 버전을
순서대로 넣습니다. FCH-256과 FCH-512는 계속 서로 다른 출력 영역을 사용합니다.

출력 마무리는 요청 출력 바이트 수를 counter로 사용하고 출력 플래그와 final
플래그를 함께 설정해 이 128바이트 레코드를 압축합니다.

### 12.4 점진적 계산

전체 메시지를 저장하지 않고도 같은 정규 트리를 계산할 수 있습니다.

1. 완성된 1,024바이트 리프의 상태와 구조 정보를 스택에 넣습니다.
2. 스택 위의 두 항목이 인접한 같은 크기의 2의 거듭제곱 리프 범위를 가지면
   하나로 결합합니다.
3. final에서 기존 패딩을 남은 부분 리프에 붙입니다. 패딩이 리프 경계를
   넘으면 리프를 하나 더 만듭니다.
4. 스택에 남은 항목을 오른쪽부터 결합합니다.

마지막 오른쪽 결합은 다음과 같습니다.

```text
root = 스택의 가장 오른쪽 항목
다른 항목이 남아 있는 동안:
    root = Node(남은 항목 중 가장 오른쪽 항목, root)
```

이 절차는 `Tree(0, leaf_count)`와 정확히 같은 결과를 만듭니다. 각 2의 거듭제곱
크기마다 완성된 서브트리가 최대 하나만 스택에 남으므로 트리 상태는
`O(log leaf_count)`만 사용합니다. 출력 마무리에서는 원본 길이와 패딩된 길이를
결합하고 출력 영역도 계속 분리합니다.

### 12.5 보안 및 호환성 영향

새 스케줄은 의도적으로 버전 1과 다른 해시 결과를 만듭니다. C 구현, Python
레퍼런스, 예상 출력, 인코딩 테스트와 이 사양서의 규범 부분을 한 번의 구현
단계에서 함께 바꿔야 하며, 두 버전을 섞어 계산하는 동작은 허용하지 않습니다.

이진 트리 자체만으로 안전성이 보장된다고 주장하지는 않습니다. 이 스케줄의
목적은 구조에 관한 근거를 분명하게 만드는 것입니다. 메시지 값으로 토폴로지를
고를 수 없고, 리프와 노드 입력이 다른 형식으로 인코딩되며, 위치와 길이가
상태에 들어가고, 루트는 메시지 전체 범위를 결합합니다. 1,024바이트 청크는
