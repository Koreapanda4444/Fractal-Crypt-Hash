# 검증 및 보안 상태

이 문서는 실제로 확인한 항목, CI에만 구성된 항목, 아직 설계 목표나 열린 문제로
남은 항목을 구분합니다. 규범 알고리즘은 [fch_spec.ko.md](fch_spec.ko.md), 상세
분석 근거는 [security_analysis.ko.md](security_analysis.ko.md)에 있습니다.

상태 기준일은 **2026-09-22 UTC**입니다. 이 기록은 로드맵 15번까지 반영한 작업
트리에 적용됩니다. 작업 트리의 기준 커밋은
`1eca2595f3f59c5e75135cdb621617d14f9242c9`이지만, 그 뒤의 커밋되지 않은 로드맵
변경도 포함합니다. 따라서 기준 SHA만으로 검증한 바이트를 식별할 수 없습니다.
외부 검토에서는 이후 만들어질 정확한 커밋이나 전달된 압축 파일과 체크섬을
고정해야 합니다.

## 상태 표기

| 표기 | 의미 |
| ---- | ---- |
| 설계 목표 | 구조가 달성하려는 보안 수준이며 확인된 결과가 아님 |
| 확인된 형식 성질 | 지정된 인코딩이나 정규 스케줄에서 나오며 구현과 대조한 성질 |
| 조건부 분석 | 명시한 이상적 함수 또는 공격 모델 안에서만 성립 |
| 관측 결과 | 제한된 테스트나 탐색에서 재현한 출력이며 범위 밖을 증명하지 않음 |
| 로컬 통과 | 아래에 기록한 환경에서 직접 재현함 |
| CI 구성됨 | 워크플로에 검사가 있지만 커밋되지 않은 현재 스냅샷이 Actions에서 실행됐다는 뜻은 아님 |
| 미확립 | 현재 증명, 독립 검토 또는 충분한 실험 근거가 없음 |

## 보안 주장 요약

| 주장 | 현재 상태 | 근거와 한계 |
| ---- | --------- | ----------- |
| FCH-256 목표: 충돌 `2^128`, 원상·제2원상 `2^256` | 설계 목표 | 이상적 출력의 일반 비용 규모일 뿐 실제 압축 함수에 대한 환원이 없음 |
| FCH-512 목표: 충돌 `2^256`, 원상·제2원상 `2^512` | 설계 목표 | 구조 정보와 호환되는 제2원상 함수 계산 `2^512` 규모도 이상적 역할별 함수 모델을 조건으로 함 |
| 패딩의 단사성과 패딩 길이마다 하나인 정규 트리 | 확인된 형식 성질 | 길이 필드, 마커, 고정 리프와 결정적 분할 규칙으로 정해지며 경계·인코딩 테스트와 일치 |
| 고정 정규 표적에서 구조 정보마다 호환 상태 하나(`kappa = 1`) | 확인된 형식 성질 | 역할과 범위 결합으로 구조 정보가 유일하며 고정 프로필이 대표 트리를 열거함 |
| C와 Python 기준 구현 일치 | 관측 결과 | 고정 시드 3개로 384회 비교했지만 두 구현이 같은 설계 오류를 공유할 수 있음 |
| 정식 16라운드의 충돌·원상·제2원상 저항성 | 미확립 | 제한된 탐색에서는 붕괴를 찾지 못했지만 전체 공간의 비용을 정하지 못함 |
| 축소 라운드 동작 | 관측 결과 | 1라운드는 약함으로 표시하며, 2~16라운드에서 확인한 라운드·입력군 결과 150개는 고정 한계값을 통과 |
| 장문·멀티콜리전·herding·grafting·다중 표적 저항성 | 관측 결과 | 현재 결정적 탐색에서 완전 일치는 없었지만 표본 수로 점근적 저항성을 증명하지 못함 |
| 양자 공격 저항성 | 조건부 분석 | 일반 쿼리와 기회 계산만 있으며 가역 회로 자원 추정이나 FCH 전용 증명이 없음 |
| 실서비스 적합성 또는 표준화 | 미확립 | 독립 암호 검토, 표준화 절차와 실서비스 배포 검토가 완료되지 않음 |

## 로컬 재현 환경

| 항목 | 값 |
| ---- | -- |
| 운영체제 | Ubuntu 24.04.3 LTS, Linux 6.18.44, x86-64 |
| C 컴파일러 | GCC 13.3.0 |
| Python | 3.12.14 |
| Z3 | 4.13.1 |
| Sanitizer | GCC AddressSanitizer와 UndefinedBehaviorSanitizer |
| Clang/libFuzzer | 이 로컬 환경에 없음 |
| 누수 검사 | 실행하지 않음. sanitizer 프로필이 `ASAN_OPTIONS=detect_leaks=0`을 사용함 |

아래 결과는 이 환경에서 재현했습니다. `PASS`는 이름을 적은 명령이 그 명령에
내장된 판정 기준을 만족했다는 뜻으로만 사용합니다.

| 명령 또는 묶음 | 로컬 상태 | 재현 범위 |
| -------------- | --------- | --------- |
| `make check` | PASS | 일반 C 테스트 13개와 CLI 입력·오류 처리 |
| `make check-extended` | PASS | 길이 변화, 깊이 확산, 스트레스, 분할 민감도 확장 테스트 4개 |
| `make check-reference` | PASS | 고정 시드 3개를 사용한 C/Python 비교 384회 |
| `make check-trails` | PASS | 1~8라운드의 고정 8비트 입력군 2개와 보고된 증거의 Z3 재검산 |
| `make check-characteristics` | PASS | 1~8라운드에서 기준 입력 32개와 단일 비트 후보 1,024개, 1라운드 약함·2~8라운드 통과 |
| `make check-reduced-rounds` | PASS | `reduced-round-v1` 160행과 정확히 일치, 1라운드 10행 약함·나머지 150행 통과 |
| `make check-second-preimage-bounds` | PASS | 길이 프로필 9개와 열거한 정규 트리 7개, `kappa = 1` 조건부 계산 |
| `make bench-check` | PASS | 원샷·스트리밍 빠른 검사 32개와 힙·할당 불변식 |
| `make bench-baseline-check` | PASS | 기준선 스키마·비교 로직 단위 테스트 6개, 이식 가능한 성능 기준선은 아님 |
| `make timing-check` | PASS | 같은 길이 내용 경로 4개가 설정된 중앙값 시간 비율 1.50 미만을 유지 |
| `make analyze` | PASS | 소스·테스트 번역 단위 31개에 대한 GCC 경로 기반 분석과 경고 오류 처리 |
| `make sanitizer-check SANITIZER_CC=gcc` | PASS | 일반·확장 묶음을 ASan+UBSan으로 실행, 누수 검사는 제외 |

## CI 범위와 현재 스냅샷의 차이

기본 워크플로에는 빌드·테스트 매트릭스 3개와 sanitizer, 정적 분석·시간,
fuzz-smoke, Windows, 32비트 x86, big-endian 작업을 합친 실행 9개가 있습니다.
확장 워크플로에는 암호분석 작업 3개가 더 있습니다. 이 경로들은 유용한 검사
범위이지만, 현재 로드맵 작업 트리는 커밋되지 않았고 GitHub Actions에서 실행되지
않았습니다.

| 환경 또는 작업 | 저장소의 구성 | 현재 스냅샷의 근거 |
| -------------- | ------------- | ------------------ |
| Linux x86-64, GCC | 전체 일반·확장 테스트, 벤치마크와 기준 분석 | 로컬 재현함 |
| Linux x86-64, Clang | 전체 일반·확장 테스트와 벤치마크 | CI 구성됨, 로컬 미재현 |
| macOS, Clang | 전체 일반·확장 테스트와 벤치마크 | CI 구성됨, 로컬 미재현 |
| Windows, UCRT64 GCC | 전체 묶음, 벤치마크와 네이티브 바이너리 stdin 검사 | CI 구성됨, 로컬 미재현 |
| Linux 32비트 x86, GCC | `-m32` 전체 묶음과 벤치마크 | CI 구성됨, 로컬 미재현 |
| QEMU big-endian PowerPC | 선택한 기능·실패 경로 바이너리 8개 | CI 구성됨, 로컬 미재현 |
| Clang ASan/UBSan | 일반·확장 묶음 | CI 구성됨, 로컬은 GCC sanitizer로 통과 |
| Clang libFuzzer 대상 5개 | 대상마다 1,024회, 입력 하나 제한시간 10초 | CI 구성됨, 로컬 미재현 |
| 확장 암호분석 | 네이티브 탐색과 전 라운드 trail·확대 characteristic 작업 | CI 구성됨, 로컬에서는 기본 프로필만 재현 |

커밋된 리비전에서는 그 정확한 SHA에 연결된 GitHub Actions 검사가 CI 상태의
근거입니다. 워크플로 파일이 있다는 사실만으로 통과했다고 기록하지 않습니다.

## 명시적으로 확인하지 못한 항목

- 고정된 리비전을 대상으로 한 독립 암호 검토를 완료하지 않았습니다.
- 실제 ARX 압축 구조와 조건부 상한의 독립 무작위 역할별 함수 사이를 잇는 증명이
  없습니다.
- 자동 차분·선형·rebound·meet-in-the-middle·트리 탐색은 전체 입력 공간이 아닌
  고정되고 제한된 입력군을 다룹니다.
- 현재 스냅샷에서 장시간 coverage-guided fuzzing, LeakSanitizer 또는 동등한 누수
  검사, 하드웨어 카운터 실행 시간 분석을 완료하지 않았습니다.
- 시간 검사는 상수 시간 또는 부채널 인증이 아닙니다.
- 구체적인 양자 게이트, 깊이, 큐비트, 메모리와 오류 정정 추정이 없습니다.
- 저장소 안의 Python 기준 구현 외에 독립된 두 번째 구현이나 외부 상호운용성
  말뭉치가 없습니다.

## 재현 방법

`build/`에서 로컬로 재현한 묶음은 다음과 같습니다.

```sh
make clean
make check
make check-extended
make check-reference
make check-trails
make check-characteristics
make check-reduced-rounds
make check-second-preimage-bounds
make bench-check
make bench-baseline-check
make timing-check
make analyze
make sanitizer-check SANITIZER_CC=gcc
```

`make fuzz-smoke`에는 libFuzzer를 지원하는 Clang이 필요합니다. 성능 수치는 시스템에
따라 달라지므로 결정적 출력, 자원 불변식, 스키마와 같은 환경끼리의 비교만 재현
가능한 결과로 취급해야 합니다.
